📖 改ざん検知ロジック解説

① まず「PDFの構造」を知ろう

PDFファイルは実はテキストベースのデータで、4つのパーツで成り立っています。

%PDF-1.7            ← ヘッダー（「私はPDFです」という宣言）

1 0 obj             ← オブジェクト（文章・画像・フォントなどの部品）
  << /Type /Page >>
endobj

xref                ← 相互参照テーブル（「部品がどこにあるか」の目次）
  0000000009 0000

trailer             ← トレイラー（「目次はここです」という案内）
  << /Size 5 >>

startxref           ← 目次の場所（バイト位置）
  123
%%EOF               ← ファイルの終わり

② チェック① xref（相互参照テーブル）

何をチェックしているか
「目次（xref）と本文の対応が正しいか」を確認します。

startxref
  12345   ← 「12345バイト目にxrefがある」と書いてある

ここで指定されたバイト位置に実際に xref がなければ異常です。

なぜ改ざん検知になるか
改ざんするとファイルの長さが変わります。するとバイト位置（12345）がずれて、指定位置に xref が見つからなくなります。目次ページを破り取って別のページを差し込んだようなイメージです。

③ チェック② trailer（トレイラー辞書）

何をチェックしているか
ファイル末尾の「案内板」が存在するかを確認します。

trailer
<<
  /Size 10        ← オブジェクトは全部で10個
  /Root 1 0 R     ← 文書の起点は「1番オブジェクト」
>>

なぜ改ざん検知になるか
trailerがない・壊れているということは、ファイルの末尾が切り取られたか、別のファイルと無理やり結合された可能性があります。

④ チェック③ stream（ストリームオブジェクト）

画像・フォント・ページ内容などのバイナリデータ（ストリーム）が壊れていないかを2段階で確認します。

ステップ1：長さの確認

<< /Length 500 >>    ← 「このデータは500バイト」と宣言
stream
...（実際のデータ）...
endstream

宣言値500と実際のバイト数が2バイト以上ずれていたら異常です。データを途中で書き換えると長さが変わります。

ただし /Length が間接参照（例: /Length 29 0 R）で記述されている場合は、スキャナー生成PDFで一般的な記述形式のためチェックをスキップします。

ステップ2：圧縮データの展開確認

PDFのデータはほとんど「FlateDecode（zlib圧縮）」で圧縮されています。正規のPDFなら必ず展開できます。展開に失敗する = データが破損・改ざんされています。

⑤ チェック④ PDF構造チェック

4-1. ヘッダー確認

ファイルの先頭が %PDF- で始まるかチェックします。これがなければPDFとして無効です。

4-2. EOFマーカー確認

ファイル末尾1024バイトに %%EOF があるかチェックします。正常なPDFは必ずこれで終わります。

4-3. オブジェクト番号の重複チェック

1 0 obj ... endobj   ← 1番オブジェクト
2 0 obj ... endobj   ← 2番オブジェクト
1 0 obj ... endobj   ← また1番？→ 異常！

同じ番号が2回出てくる場合、元のオブジェクトの上に偽のオブジェクトが追加された疑いがあります。

⑥ チェック⑤ 増分更新（インクリメンタルアップデート）

PDFの「追記」機能とは
PDFには、元のデータを消さずに末尾に差分を追記できる仕様があります。電子署名でよく使われます。

（元のPDF）
%%EOF        ← 1つ目の終端

（追記されたデータ）
%%EOF        ← 2つ目の終端

なぜ危ないのか
%%EOF が2個以上あれば増分更新です。正規の用途（電子署名）もありますが、署名済みPDFに後から内容を追記するという改ざん手口にも使われます。そのため「疑い」として警告します。

⑦ チェック⑥ 印刷→再PDF化の検知

どんな改ざん手口か

元のPDF → 印刷 → スキャン or スクリーンショット → 新しいPDFとして保存

こうすると文字データが画像に変わり、内容を自由に差し替えやすくなります。

何を手がかりにするか（6つのスコア指標）

指標内容
Producer/CreatorMicrosoft Print to PDF など印刷系ソフト名が記録されていないか
大きなCTM変換行列ページ全体を覆うサイズの画像配置命令があるか
テキスト演算子なし文字を描く命令（Tj/TJ/Tf/BT）が一切なく画像命令（Do）だけか
白矩形＋画像白い四角で元テキストを隠して画像を上に重ねるパターンがあるか
フォントなしフォントデータが存在せず画像だけか
XObjectが画像のみ埋め込みオブジェクトがすべて画像種別か

スコア判定と改ざん判定への影響：

疑い度スコア改ざん判定理由
高（スキャナー）7以上なし（正常）複合機スキャン等の正常運用とみなす
中4〜6あり印刷・再PDF化による内容差し替えの疑いが高い
低2〜3疑い再PDF化の可能性あり
なし0〜1影響なし—

⑧ チェック⑦ 画像ズレ検知（手動貼り付けの検出）

どんな改ざん手口か
AcrobatなどのPDF編集ソフトで、特定の文字や数値の上に画像を貼り付けて隠す手口です。たとえば金額「1,000円」の上に「10,000円」と書かれた画像を貼る。

PDFの画像配置の仕組み（CTM変換行列）

[a  b  0]
[c  d  0]  → a=幅, d=高さ, e=X座標, f=Y座標, b/c=傾き
[e  f  1]

4つの検出指標

指標1：非整数座標
正規のPDFは画像をキリのよい座標に配置します。手動で貼り付けると x=12.37pt, y=307.82pt のような中途半端な値になりやすいです。小数部分が0.5ptを超えていたら怪しいと判断します。

指標2：微小な傾き
マウスで貼り付けると画像がわずかに傾くことがあります。CTM行列のb/c成分が0でない場合（0.01〜20の範囲）に傾きありと検出します。

指標3：隣接画像間の隙間・重複
元のページを複数の画像に分割して貼り直した場合、画像の境界に隙間や重複が生じます。1.5ptを超える隙間または重複を検出します。

指標4：ページ枠からのズレ
正規のPDFは画像がページ端にぴったり合います。1〜30ptの微妙なズレは手動配置を疑わせます。

スコア判定：

疑い度スコア改ざん判定への影響
高6以上疑い（印刷再PDF化「なし」の場合）
中3〜5疑い（印刷再PDF化「なし」の場合）
低1〜2注意（印刷再PDF化「なし」の場合）
なし0影響なし

なお、印刷再PDF化「高」（複合機スキャン扱い）と判定された場合は、スキャナー誤差とみなして画像ズレ判定は改ざん判定から除外されます。

⑨ 総合判定のロジック

各チェック結果を以下の優先順位で組み合わせます。

● xref・trailer・stream・構造 のどれかNG
  → 「異常検出」（改ざん: あり）

● 増分更新（%%EOFが複数）
  → 「警告: インクリメンタルアップデート検出」（改ざん: 疑い）

● 印刷再PDF化 「中」
  → 「異常検出: 印刷→再PDF化の疑い（確度=中）」（改ざん: あり）

● 印刷再PDF化 「低」
  → 「警告: 印刷→再PDF化の可能性（確度=低）」（改ざん: 疑い）

● 印刷再PDF化「なし」かつ 画像ズレ 高 or 中
  → 「警告: 手動画像貼り付けの疑い」（改ざん: 疑い）

● 印刷再PDF化「なし」かつ 画像ズレ 低
  → 「注意: 手動画像貼り付けの可能性（低）」（改ざん: 注意）

● 全て問題なし（または印刷再PDF化「高」＝複合機スキャンのみ）
  → 「正常」（改ざん: なし）

※ 印刷再PDF化「高」（スコア7以上）は複合機スキャン等の正常運用とみなし、画像ズレもスキャナー誤差として改ざん判定から除外します。

⑩ SHA-256ハッシュについて

SHA-256は改ざん検知には使わず、証拠保全のための記録です。ファイルの全バイトを計算式に通すと64文字の「指紋」が得られます。1バイトでも変わると全く異なる値になるため、後から「このハッシュ値のPDFは確かに改ざんされていない」という証跡として利用できます。

元ファイル  → a3f8c2d1e4b79f31...
改ざん後    → 9e1k5p2q8m3x7r2... ← 全然違う値

表示は先頭16桁のみですが、CSVには64桁全て記録されます。
