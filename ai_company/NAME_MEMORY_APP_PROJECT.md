# 人名記憶トレーニングアプリ プロジェクト計画

## 1. プロジェクト概要

**目的：** オリジナルの親しみやすいキャラクターと短時間の練習を通じて、人の名前を覚える練習を支援するアプリを企画・開発し、顧客ニーズと販売可能性を検証する。

**現時点の方針案：** まずスマートフォン対応のWebアプリとして、架空の人物名を使った個人向け試作を行う。小規模事業者やコミュニティ運営者への聞き取りで実際の利用場面を確認する。実名名簿、チーム共有、サーバー同期は、必要性とプライバシー・運用要件が確認できるまで初期MVPに含めない。

この計画は部門横断の初期提案であり、顧客調査・市場調査・法的確認・実装見積もりを完了したものではない。以下の顧客像、価格、日程、KPIは検証用の仮説であり、確約ではない。

## 2. 顧客・利用者仮説

| 優先度 | 顧客・購入判断者（仮説） | 利用者・利用場面 |
|---|---|---|
| 初期検証 | 接客・サービス業など小規模事業者の店長、研修担当者 | 新人が同僚・担当者・常連客の名前を覚える練習 |
| 初期検証 | 小規模コミュニティ、スクール、地域団体の運営者 | 新規参加者の名前を覚える練習 |
| 次点 | 営業、採用、顧客対応を行う中小企業の部門責任者 | 商談相手、同僚、候補者の名前を覚える練習 |

**価値仮説：** 3〜5分程度の想起練習と復習が、名前を覚えるための取り組みを始めやすくし、継続する助けになる。

**未確認事項：** 困りごとの頻度と深刻さ、キャラクターの業務適合性、架空名での練習が実際の対人場面に役立つか、利用継続性、購入者と予算、支払意思。

## 3. MVP案

### 含める機能

- 日本語のスマートフォン対応Web UI（PWA化は実装環境と要件を確認して判断）
- 架空の人物名・読み・オリジナルキャラクターによる練習コンテンツ
- 名前を見て覚える、名前を思い出して答える、正解を確認する基本フロー
- 間違えた名前を優先する簡易復習
- 練習状況の表示と、学習データの個別・全件削除
- 読みやすい文字、十分なコントラスト、色だけに頼らない正誤表示、動きを抑える配慮

### 初期対象外

- 実在する顧客・同僚の実名名簿、写真、連絡先の登録
- アカウント、サーバー保存、端末間同期、チーム共有、管理者権限
- CRM・人事システム連携、顔認識、外部データ収集、AIによる人物推測
- 効果を保証する表示や、学習成果を裏付けなく断定する広告

架空名の試作だけでは、実際に会う人の名前を覚える効果を検証できない。パイロットで実名やチーム利用の必要が確認された場合は、実装や販売を約束せず、後述の判断ゲートに進む。

## 4. プライバシー・データ方針

- 初期試作では架空名を使い、名前や学習履歴を端末内に保存する構成を第一候補とする。外部送信・解析ログへの記録は行わない設計を受け入れテストで確認する。
- 端末内保存であっても、共有端末・端末紛失・ブラウザデータ消去等のリスクは残る。保存場所と削除方法を説明し、機密情報を入力しない試用条件を明示する。
- 実名を扱う機能を追加する場合は、利用目的、必要な項目、閲覧範囲、保存期間、削除手順、委託先・ログ・バックアップを事前に整理する。必要に応じて専門家に確認し、法令適合を未確認のまま断言しない。
- 実名・チーム利用は、要望があるという理由だけで実装しない。追加投資・リスク評価後にGo/No-Goを判断する。

## 5. 開発・検証ロードマップ

| 段階 | 期間目安 | 主な作業 | 完了・判断条件 |
|---|---:|---|---|
| 0. 課題確認・要件定義 | 1〜2週間 | Salesが候補者5〜10組織に聞き取り。Designが利用フローを整理。Engineeringが保存・削除・配信方式と見積もりを精査 | 最優先の利用場面、試作対象、成功指標、実名を扱わない試験条件を合意 |
| 1. UX・キャラクター試作 | 1〜2週間（並行可能） | 画面プロトタイプ、名前とキャラクターの表示案、操作テスト。既存作品に依存しないデザイン制作・確認 | 初見の利用者が練習を開始・完了でき、主要な表示・操作上の問題を記録 |
| 2. MVP実装 | Engineering 12〜18人日を初期目安 | 端末内保存、練習・回答・簡易復習、状態表示、削除、主要画面の実装 | 受け入れ基準を満たす試用版。Design・キャラクター制作、顧客調査工数は別途 |
| 3. 小規模パイロット | 2〜4週間を仮置き | 架空名で試用し、利用状況とインタビューを確認。実名・機密データを入力しない | 操作性、再利用、課題との適合、キャラクターの受容性を評価 |
| 4. 商用化判断 | パイロット後 | KPI・顧客要望・コスト・運用負担をレビュー | 継続開発、対象変更、またはチーム／実名対応の追加調査・投資を判断 |

Engineeringの初期見積もりは、要件・プライバシー整理1〜2人日、基盤・データ設計2〜3人日、学習フロー4〜6人日、UI・進捗・削除3〜4人日、テスト・公開準備2〜3人日で、合計12〜18人日程度。1人主担当の場合の暦日は概ね3〜5週間の仮説で、仕様、既存環境、レビュー、正式なキャラクター制作によって変わる。要件確定後に再見積もりする。

## 6. 受け入れ基準とKPI

### MVP受け入れ基準

1. 利用者が架空の名前で練習、回答、答え合わせ、復習を完了できる。
2. ページ再読み込み後も端末内の学習状態が保持され、削除したデータは一覧・出題対象から消える。
3. 名前・読み・手がかりをサーバー、解析イベント、アプリログに送信・記録しないことを確認する。
4. 主要なスマートフォン幅で操作でき、日本語の表示・入力に重大な問題がない。
5. 初見の利用者テストで、初回練習のつまずきを特定し、重大な操作障害を解消する。

### パイロットで見る指標

- **課題適合：** 名前を覚えたい場面、その頻度、現在の代替手段、具体的な困りごと
- **操作性：** 初回練習完了、操作上のつまずき、登録・削除の理解
- **継続性：** 数日後・翌週の再利用、復習完了、継続しない理由
- **価値：** 利用者の主観的な有用性、再利用意向、支払意思
- **訴求：** LP閲覧者からインタビュー・試用に進む割合、業種別の反応
- **要件発見：** 実名、共有、同期、管理機能が必要となる具体的な業務と頻度

初期サンプルは小規模なので、結果を市場全体の需要や学習効果の証明として扱わない。数値目標は基準値を得てから設定する。

## 7. 販売・マーケティング方針

### ポジショニング案

「人の名前を覚える練習を、オリジナルキャラクターと短い時間で続けやすくするアプリ。」

「必ず覚えられる」「記憶力が上がる」「接客成果が向上する」とは訴求しない。実際に提供している機能、保存方法、検証段階を正確に説明する。

### 初期チャネル

1. Sales主導で、店長・研修担当者・コミュニティ運営者に個別ヒアリング（まず5〜10組織を候補とする）。
2. 顧客候補の紹介を地域事業者ネットワーク、業界コミュニティ、研修関係者に依頼する。
3. ニーズが確認できた場面に絞り、先行テスト募集ページと架空名のデモを用意する。
4. note・SNS等では、利用場面の問いかけ、キャラクター制作方針、試用で分かったことを発信する。効果の断定や実名入力の誘導は避ける。

### LP構成・コピー案

- **見出し：**「名前を覚える練習、まずは数分から。」
- **説明：**「オリジナルキャラクターと一緒に、人の名前を思い出す練習をするアプリです。」
- **CTA：**「先行テストに参加する」
- 課題場面、使い方（登録→練習→復習）、開発中であること、データ保存・削除方針、試用条件を記載する。
- 実名を扱わない試用中は、架空名のデモを使う。実際の保存・送信仕様を検証してからプライバシー表現を確定する。

### 価格・販売モデル仮説

| 案 | 仮説レンジ・条件 | 扱い |
|---|---|---|
| 個人向け | 無料試用＋有料版月額500〜1,000円程度 | 支払意思を聞くための仮説。端末内保存の試作だけで定期課金を開始する判断はしない |
| 小規模チーム向け | 月額3,000〜10,000円程度、または人数課金 | 実名・共有・管理機能の要件と追加開発・運用費が未確定のため、将来の価格調査用に留める |
| パイロット | 2〜4週間の試用。有償化する場合は支援範囲・対価を個別に明示 | 顧客課題と購入判断を検証。試作の制約を事前説明し、未実装機能は約束しない |

これらの価格は市場調査済みの相場ではなく、検証用の提案値である。代替手段、導入決裁者、予算、支払意思、提供コストを確認して見直す。

## 8. 主要リスクと判断ゲート

| リスク | 対応・判断 |
|---|---|
| 架空名での練習が実際に人の名前を覚える用途につながらない | パイロットで学習体験と実利用ニーズを分けて確認。架空名の成績だけで実務効果を主張しない |
| 実名やチーム機能がないと顧客価値が成立しない | 具体的な必要業務・頻度を記録。サーバー、権限、データ保護、運用費を再設計し、別途Go/No-Go |
| 端末内保存でも共有端末・紛失等の懸念が残る | 保存先・削除・利用上の注意を明示し、初期試験は架空名とする |
| キャラクターが幼すぎる、または既存作品に似る | 職場利用者の受容性をテストし、独自の形・色・設定を制作。類似性と利用権を確認 |
| 価格・継続性が成立しない | 先行試用、再利用、具体的な支払意思を確認してから販促投資を増やす |
| 学習効果やプライバシーを過剰に約束する | コピーを実装・検証済みの事実に限定。必要な法務・専門家確認を商用化前に行う |

### 実名・チーム版の追加投資ゲート

パイロットで実名または共有の具体的な需要が複数の顧客候補から確認された場合に限り、(1)利用目的と必要データ、(2)本人・管理者の閲覧権限、(3)保存・削除・バックアップ、(4)セキュリティ・運用責任、(5)顧客側の導入条件、(6)追加開発費と価格受容性を整理する。法的・プライバシー面の確認を含む追加投資案を作り、別途Go/No-Goを決定する。

## 9. 直近のアクション

1. Salesが候補顧客5〜10組織にインタビューし、利用場面・現行の工夫・購入判断者を記録する。
2. Designが主要画面とオリジナルキャラクターの方向性をプロトタイプ化し、職場での受容性とアクセシビリティを確認する。
3. Engineeringが既存の実装環境を確認し、端末内保存・削除・送信なしの設計と工数を再見積もりする。
4. 顧客ヒアリング後に対象場面とMVPの受け入れ基準を確定し、試作の実装可否を判断する。
5. Marketingは実装・検証の範囲内で先行テスト募集ページを作り、プライバシー案内と誇張のないコピーを準備する。
6. 小規模試用の結果をCEOが統合し、継続開発・対象変更・実名／チーム版検討のいずれかを判断する。
